## Context

`td-053` measured the gap: `dashboard/src` carried thousands of lines of
TypeScript, TSX and CSS with **no** linter or formatter configuration at any
level in the repo — verified by searching for `biome.json`, `eslint.config.*`
and `.prettierrc*` outside `node_modules` and finding nothing. `npm run build`
runs `tsc --noEmit`, so the shipped TypeScript was type-checked but neither
linted nor format-checked, while the Python half of the same repo was gated by
`ruff check` **and** `ruff format --check` as two of `make verify`'s steps.

By the time this was acted on the tree had grown to ~36k lines across 154
source files, all written without a style gate — which is exactly the
amplifier `td-053` was filed on.

## Decision

Adopt **Biome, pinned to the exact version `2.5.11`** in
`dashboard/package.json`, as the single lint + format tool for `dashboard/`.
Configure it in `dashboard/biome.jsonc` from **measurements of the existing
tree**, and wire `biome check` into both the local canonical chain
(`make dashboard-lint`, a prerequisite of `make verify`) and CI
(`.github/workflows/dashboard.yml`, as the first job step).

Three sub-decisions carry the weight:

1. **One binary, not two.** `biome check` lints and format-checks in a single
   pass, so `npm run lint` is the entire style gate. `format:check` exists as
   the narrower escape hatch, not as a second required step.
2. **Codify, do not import.** Every formatter value was measured, not chosen:
   reformatting `src/` at widths 70/76/80/84/90/100/120 changed
   10371/6770/4597/4925/5558/6689/8657 lines, so `lineWidth: 80` — the
   minimum, and Biome's own default — was adopted. Double quotes (~9.5k vs
   ~140), semicolons (~9.3k terminated lines) and 2-space indent were measured
   the same way.
3. **Triage the lint rules, and record the triage in the config.** Start from
   `recommended`; fix the findings that are real defects; disable the five that
   would churn for taste — each with its finding count and reason written
   beside it in `biome.jsonc`.

`src/processModel.ts` is excluded because it is generated by
`scripts/generate_process_model_ts.py` and gated by its own
`git diff --exit-code`: formatting a generated file would leave the generator
permanently dirty against that gate.

## Considered Options

### Biome (chosen)

- **Pro**: one binary for lint + format + CSS; no plugin graph to maintain;
  fast enough (~0.15s over 162 files) that it can lead the `verify` chain
  rather than trail it; TypeScript- and JSX-native without a parser plugin;
  matches this repo's existing single-binary taste (`ruff`, `uv`).
- **Con**: smaller rule catalogue than the ESLint ecosystem; no
  `eslint-plugin-react-hooks` equivalent, so exhaustive-deps is not covered;
  config comments require the `.jsonc` filename.

### ESLint + Prettier

- **Pro**: the largest rule ecosystem; `react-hooks` rules would apply to the
  Preact tree; the Praxion asset set ships a config for it.
- **Con**: two tools, two configs, two CI steps and a plugin dependency graph
  to keep in sync — for a single-package UI with no framework-specific
  linting need yet. The one capability it uniquely buys (exhaustive-deps) can
  be added later without unpicking the formatter choice.

### Prettier alone (format, no lint)

- **Pro**: the smallest possible change; zero triage work.
- **Con**: leaves the *lint* half of `td-053` open. The mechanical sweep found
  real defects — an implicit `any`, an ignored-by-role `aria-label` in three
  places, a redundant condition — that a formatter alone would never surface.

## Consequences

**Positive.** The TypeScript/CSS half of the tree is gated the way the Python
half already was, enforced twice (local `make verify`, CI). The one-time
normalization is paid now, as a reviewable style-only commit, instead of
smearing across future behavioural diffs. Nine real defects were fixed on the
way in. The config is self-documenting: a future reader sees each disabled
rule's finding count and reason next to it.

**Negative.** A large one-time diff — 84 files reformatted, ~4.6k changed
lines — which will bury this range in `git blame`. `make verify` now requires
the dashboard's dev dependencies for contributors (users still need no Node
toolchain); the target fails loudly with the install command rather than
skipping. And five recommended rules are off, so the gate is narrower than
"Biome recommended" — the reasons are in the config, but they are a standing
invitation to re-examine.

## Disconfirmation

**Falsifier.** A defect class that ESLint's ecosystem catches and Biome does
not, landing in `dashboard/` and reaching a user. The concrete candidate is
`react-hooks/exhaustive-deps`: this tree is dense with `useEffect` polling
loops, and a stale-closure bug there would be exactly the miss that says the
rule catalogue, not the tool count, should have driven the choice.

**Steelmanned runner-up.** ESLint + Prettier is the stronger choice if the
dashboard's future defects are hook-lifecycle defects rather than style
defects. The tree already carries several hand-rolled polling effects
(`visibilityPausedPoll.ts`, per-lane status polls); exhaustive-deps is the
single most valuable rule for that shape of code and Biome has no equivalent.
The two-tool cost is real but bounded — two config files and one extra CI
step — and Prettier's formatting is a superset of what was adopted here
anyway. The counter is only that the cost is paid every day and the benefit is
hypothetical until a stale-closure bug actually ships.

**Reversal trigger.** Revisit if (a) a stale-closure or dependency-array bug
reaches a user, or (b) the disabled-rule list grows past ~8 entries, which
would mean `recommended` and this codebase have diverged enough that the
preset is no longer doing useful work.
